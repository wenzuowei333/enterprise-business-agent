# 三个设计取舍

## 1. 确定性事实与模型解释分开

**问题：** 返回一段流畅解释，不能证明读取了合法证据，也不能证明引用存在。

**方案：** 后端复检库存规则并生成带版本的证据；只向 Provider 投影允许字段，维护合法引用；按结构、引用和建议约束校验输出。写入前再核实来源与证据版本。

**原因与代价：** 让判断可以回到原始事实，代价是字段白名单和版本契约需要维护。证据不足就暴露缺口，不通过重写提示词强行填满结论。校验不提供事实真实性或模型准确率保证。

**验证：** [非法输出拒绝](../tests/test_diagnosis_boundaries.py#L32)；[执行中证据变化](../tests/test_diagnosis_boundaries.py#L81)；[输入契约](../backend/app/services/evidence_contract.py#L416)。

## 2. PostgreSQL 队列与带代次租约

**问题：** Worker 中断后需要接管，但先前的进程恢复后仍可能携带旧结果。

**方案：** admission 锁与 SKIP LOCKED 领取，领取递增 attempts；心跳只续有效租约。Provider 调用释放数据库事务，写回时匹配 owner、代次、有效租约和 processing 状态。

**原因与代价：** 复用数据库完成可恢复执行，减少一个消息基础设施；短全局锁简化一致性，但吞吐受限。进程可能再次调用 Provider，不能承诺外部调用或计费严格一次。

**验证：** [真实 SIGKILL 接管](../tests/test_postgres_reliability.py#L139)、[SIGSTOP 旧结果拒绝](../tests/test_postgres_reliability.py#L158)。测试租约被缩短，只用于故障复现。

## 3. 权限在异步任务执行时重新检查

**问题：** 提交时有权限，不代表任务执行和写回时仍有权限；仅隐藏按钮会让后端绕过。

**方案：** SQL 过滤仓库范围；权威仓库来自库存快照；创建任务、读取任务和 Worker 调用前后分别授权。账号停用或撤权可使已有任务失效。

**原因与代价：** 让异步任务继承业务边界，代价是额外查询及“已提交但后续被取消”的用户体验。范围配置未知时默认拒绝。

**验证：** [未知范围默认拒绝](../tests/test_access_and_api.py#L88)、[执行中撤权拒绝写回](../tests/test_diagnosis_boundaries.py#L96)。
