# 面试讲解

## 90 秒介绍

我独立开发过面向真实业务的 ERP 系统，这个仓库把其中的库存异常诊断整理成一个可运行的脱敏切片。它先由后端按当前用户权限取案件、复检规则并生成证据，再把允许字段交给模型做结构化解释，最后验证引用、证据版本与执行归属，才保存结果。

我希望重点展示三个工程问题：第一，模型不负责直接改库存，解释必须能回到证据；第二，异步任务不能只在提交时校验权限，Worker 调用前后都要重新检查；第三，中断后的接管会产生旧 Worker，所以回写要同时核对租约、持有者和执行代次。

演示里能看到正常结果、证据不足、非法引用失败，以及只读角色的范围变化。阶段五用真实 PostgreSQL 和独立进程验证了 33 项回归，包括 SIGKILL 接管与 SIGSTOP 迟到回写拒绝。本版使用合成数据和 Mock，说明的是执行机制，不是模型准确率。原项目的通用 Agent、MCP 等后续能力没有放进这个展示切片，我会按版本边界分别说明。

## 常见追问

**为什么有租约还要代次？** Worker 标识可能复用，旧执行可能恢复；递增代次区分不同执行，最终还要检查有效租约与当前状态。

**能否保证模型只调用一次？** 不能。崩溃和接管可使调用重复。本版约束本地可见结果；外部幂等、收费对账需单独设计。

**Schema 合法是否代表答案正确？** 不代表。它只约束结构和可引用范围；根因是否成立仍需证据和人工判断，模型质量要另建评测集。

**如何扩大吞吐？** 先压测锁等待与任务时延，再考虑按业务分区缩小锁范围、数据库约束和更细粒度 admission；这些是改进方向，不写成当前已实现。
